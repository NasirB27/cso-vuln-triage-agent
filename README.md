# CSO Vulnerability Triage Agent

A LangChain/LangGraph agent that lets Cyber Systems Operations (CSO) specialists ask, in
plain English, which of their hardened container images need urgent attention — and get
back a deterministic, severity-ranked list instead of a wall of similarity-search text.

> **Data is synthetic.** All scan records, CVE IDs, and findings in this repo are
> generated by [`backend/src/scripts/generate_mock_scans.ts`](backend/src/scripts/generate_mock_scans.ts)
> for demo purposes only. They do not represent any real Iron Bank image or vulnerability.

## Why this project

Air Force CSO specialists who maintain hardened container images (in an Iron Bank-style
DoD image hardening pipeline) are often working against thousands of images, each with
its own scan history and finding count. Today, triaging "what needs my attention today"
is largely manual — scrolling scan dashboards image by image. This project is a small,
focused demo of how an LLM agent can sit on top of that data and answer "what's worst
right now" in seconds, while keeping the actual ranking logic deterministic and
auditable rather than left to the model to eyeball from retrieved text.

It's built as a fork of the [`ai-pdf-chatbot-langchain`](https://github.com/mayooear/ai-pdf-chatbot-langchain)
LangGraph template, re-skinned end to end: the ingestion graph now consumes structured
vulnerability scan data instead of PDFs, and the retrieval graph is a real tool-calling
agent instead of a semantic-similarity-only Q&A loop. It's meant as a portfolio piece
for a Deployed Engineer / Forward Deployed role — it demonstrates LangGraph state
machine design, explicit (non-LLM) ranking logic behind a tool call, and guardrails
against the model fabricating results.

## Features

- **Ingestion graph**: reads hardened-image vulnerability scan JSON (Anchore/Grype/Twistlock-shaped)
  and embeds each image as a Document whose **metadata** — not just free text — carries
  `imageName`, `overallSeverity`, `cvssMax`, per-severity finding counts, and `lastScannedAt`.
- **Retrieval graph**: a tool-calling agent. The chat model decides when to call
  `queryHardenedImages`, a tool that filters/sorts by severity and CVSS **in code**
  (severity rank primary key, CVSS secondary key, both descending) — never left to the
  LLM to infer from prose.
- **Guardrails**: if the vector store is unreachable, or the tool returns zero matches,
  the agent says so plainly instead of guessing.
- **Direct-answer path**: general questions ("what does CVSS mean?") skip the tool
  entirely instead of being forced through a vulnerability lookup.

## Architecture Overview

```ascii
INGESTION
┌──────────────────────────────┐   read scan JSON   ┌────────────────────────────┐
│ generate_mock_scans.ts       │ ──────────────────> │ ingestion_graph            │
│ (synthetic Anchore/Grype-    │                      │  - scanRecordToDocument()  │
│  style scan records)         │                      │  - embeds + writes to      │
└──────────────────────────────┘                      │    Supabase (full metadata │
                                                        │    jsonb, not just text)  │
                                                        └────────────────────────────┘

RETRIEVAL
┌──────────────────────┐  "what needs attention?"  ┌───────────────────────────────┐
│ User query            │ ─────────────────────────> │ retrieval_graph               │
└──────────────────────┘                             │  1. classifyIntent            │
                                                       │     (triage vs. direct)       │
                                                       │  2. agentStep                 │
                                                       │     model.bindTools([...])    │
                                                       │  3. executeTool               │
                                                       │     queryHardenedImages:      │
                                                       │       - pulls candidates from │
                                                       │         Supabase metadata     │
                                                       │       - explicit in-code sort │
                                                       │         (severity, then CVSS) │
                                                       │  4. agentStep (final answer)  │
                                                       └───────────────────────────────┘
```

- **Supabase** stores the vector embeddings *and* the full structured metadata (jsonb),
  so results are filterable/sortable, not just semantically similar.
- **LangGraph** orchestrates both graphs as explicit state machines you can step through
  in LangGraph Studio.
- **The ranking logic lives in `queryHardenedImages`** (`backend/src/retrieval_graph/tools.ts`),
  as a pure, unit-tested function — see [`filterAndRankImages`](backend/src/retrieval_graph/tools.ts)
  and its tests in [`backend/__tests__/retrieval_graph/tools.test.ts`](backend/__tests__/retrieval_graph/tools.test.ts).

The system consists of:
- **Backend**: A Node.js/TypeScript service with two LangGraph graphs:
  - **Ingestion** (`src/ingestion_graph/graph.ts`) — reads mock scan JSON, transforms it
    into Documents with structured severity metadata, embeds into Supabase.
  - **Retrieval** (`src/retrieval_graph/graph.ts`) — a tool-calling agent that filters/ranks
    hardened images by severity via `queryHardenedImages` (`src/retrieval_graph/tools.ts`).
  - **Configuration** (`src/shared/configuration.ts`) — shared config for model/vector store.
- **Frontend**: The template's Next.js chat UI, kept only so the backend type changes
  compile end to end — this repo's deliverable is the backend/agent architecture, not a
  new UI. The chat UI still expects a PDF-upload-shaped ingestion response and was not
  redesigned for the new data model.

## Prerequisites

1. **Node.js v18+** (v20 recommended).
2. **Supabase project** with:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - A `documents` table + `match_documents` function for vector similarity search (see
     [LangChain's Supabase vector store guide](https://js.langchain.com/docs/integrations/vectorstores/supabase/)).
3. **OpenAI API key** (or another LangChain-supported provider) — set `OPENAI_API_KEY`.
4. *(Optional)* **LangSmith API key** for tracing.

## Installation

```bash
git clone <this-repo-url>
cd cso-vuln-triage-agent
yarn install   # or: npm install --legacy-peer-deps in backend/ and frontend/ separately
```

Then configure environment variables — copy `backend/.env.example` to `backend/.env` and
`frontend/.env.example` to `frontend/.env`, filling in your Supabase/OpenAI/LangSmith
values.

## Generating and ingesting the mock scan data

```bash
cd backend
npx tsx src/scripts/generate_mock_scans.ts   # writes backend/src/sample_scans/*.json
```

This generates ~40-60 synthetic hardened-image scan records with a realistic severity
spread. To ingest them into Supabase, run the ingestion graph with `useSampleScans: true`
(e.g. via LangGraph Studio, or `yarn langgraph:dev` and invoking `ingestion_graph` with
that config).

## Local Development

### Backend

```bash
cd backend
yarn langgraph:dev
```

Launches a local LangGraph server (default port 2024) and LangGraph Studio for stepping
through both graphs.

### Frontend

```bash
cd frontend
yarn dev
```

Runs the Next.js dev server on port 3000. Note: the chat UI is the template's original
PDF-upload interface and was intentionally left unmodified beyond the type changes needed
to compile — see **Architecture Overview** above.

## Testing

```bash
cd backend
yarn test
```

Covers:
- `scanRecordToDocument` correctly attaching structured severity/CVSS metadata during
  ingestion ([`__tests__/ingestion_graph/scan_ingestion.test.ts`](backend/__tests__/ingestion_graph/scan_ingestion.test.ts)).
- `filterAndRankImages` deterministically ranking mock candidates by severity, then CVSS
  ([`__tests__/retrieval_graph/tools.test.ts`](backend/__tests__/retrieval_graph/tools.test.ts)) —
  the test I'd point to first in an interview.
- The guardrail path when the vector store is unreachable
  ([`__tests__/retrieval_graph/guardrail.test.ts`](backend/__tests__/retrieval_graph/guardrail.test.ts)).

## Customizing

- **Ranking behavior**: `queryHardenedImages`'s schema and sort logic live in
  `backend/src/retrieval_graph/tools.ts`.
- **Agent persona/instructions**: `backend/src/retrieval_graph/prompts.ts`.
- **Mock data shape**: `backend/src/scripts/generate_mock_scans.ts`.
- **Vector store**: `backend/src/shared/retrieval.ts` (swap in another provider by adding
  a retriever function and updating `makeRetriever`).
